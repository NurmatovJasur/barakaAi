# Smart Basket Optimizer

Код: [`apps/api/src/algorithms/optimizer.ts`](../apps/api/src/algorithms/optimizer.ts), [`offerEligibility.ts`](../apps/api/src/algorithms/offerEligibility.ts). Модуль чистый: нет БД и HTTP.

## Модель

- `i` — товар, `j` — поставщик
- `q_i` — потребность, `p_ij` — цена, `x_ij` — закупаемое количество
- `m_ij` — минимальный заказ, `a_ij` — доступно, `d_j` — доставка, `y_j ∈ {0,1}` — используется ли поставщик

```
min  Σ p_ij·x_ij + Σ d_j·y_j
s.t. Σ_j x_ij = q_i                  ∀i
     0 ≤ x_ij ≤ a_ij·y_j
     x_ij = 0  ∨  x_ij ≥ m_ij
```

Смешанное целочисленное программирование (полунепрерывные переменные + бинарные `y_j`).

## Алгоритм (точный)

1. **Фильтр предложений.** Исключаются: неактивный товар/поставщик, `dataQualityStatus ∈ {INVALID, EXPIRED}`, `expiresAt ≤ now`, `OUT_OF_STOCK` или `a ≤ 0`, цена старше `FRESHNESS_STALE_HOURS`, другая единица или валюта, нет доставки в район, `m > a`. Каждое исключение → предупреждение с причиной.
2. **Варианты по товару.** Для каждого непустого множества «активных» предложений товара A: допустимо, если `Σm ≤ q ≤ Σa`. При фиксированном A задача — LP с ограничениями-коробками, оптимум: всем выдать `m`, остаток заполнить по возрастанию цены до `a`. Это точное решение.
3. **Подмножества поставщиков S** (по возрастанию размера). Для каждого товара берётся самый дешёвый вариант, чьи поставщики ⊆ S. Доставка начисляется по фактически использованным поставщикам — **один раз на поставщика**, сколько бы товаров у него ни покупалось.
4. **Сценарии:**
   - `SINGLE` — |S| = 1 (Scenario A)
   - `MULTI` — без ограничений (Scenario B)
   - `BALANCED_2`, `BALANCED_3` — не более 2/3 поставщиков (Scenario C)
5. **Рекомендация** — минимальная стоимость; при равенстве — меньше поставщиков, затем более строгий лимит.

Минимум по всем S равен оптимуму MIP: если оптимальный выбор для S использует только U ⊂ S, тот же выбор с меньшей доставкой будет найден при S = U.

### Доставка поставщика

`d_j` = максимальная `deliveryCost` среди допустимых предложений поставщика в этой корзине. В демо-данных ставка одинакова для всех предложений поставщика.

## Baseline и экономия

- `baselineCost` = стоимость сценария `SINGLE` (лучшая закупка у одного поставщика).
- `savings = baselineCost − totalCost`. Может быть отрицательной.
- Если ни один поставщик не выполняет заказ целиком — `baselineCost = null`, `savings = null` (экономия не выдумывается).
- В UI экономия всегда подписана как расчётная.

## Статусы

| Статус | Значение |
| --- | --- |
| `OPTIMAL` | полный перебор, оптимальность подтверждена |
| `FEASIBLE_LIMIT_REACHED` | достигнут `OPTIMIZER_MAX_EVALUATIONS` или лимит предложений на товар; план допустим, оптимальность не подтверждена |
| `INFEASIBLE` | допустимой комбинации нет; причины в `warnings` |

## Сложность

`O(Σ_i 2^{k_i} + 2^S · n)`, где `k_i` — предложений товара (≤ 10), `S` — поставщиков. Для демо (5 поставщиков, ≤ 5 предложений) — сотни операций.

## Тесты

[`optimizer.test.ts`](../apps/api/src/algorithms/optimizer.test.ts): 12 сценариев из ТЗ + MOQ-сплит, зоны, единицы, лимит вычислений и сверка с целочисленным полным перебором на 25 случайных инстансах. Каждый допустимый сценарий проверяется на инварианты: `Σx = q`, `m ≤ x ≤ a`, доставка = сумма по использованным поставщикам, `total = products + delivery`.
